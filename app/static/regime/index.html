데이터 확인

파라미터를 고정한 채 평가일마다 그 시점 정보로만 매칭을 다시 수행해, 매칭된 날들의 +H일 수익률 중앙값을 신호로 삼고 실제 실현 수익률과 비교합니다. 전 구간을 다시 계산하므로 수십 초 걸립니다.

방법론 요약

  • Look-ahead 차단 — 외생 시계열은 forward-fill 로만 정렬(5거래일 초과 공백은 결측), 유사도 정규화(중앙값/MAD)는 기준일까지의 데이터로만 추정, 검증에서는 forward 구간이 끝나지 않은 날을 후보에서 제외합니다.
  • 유사도 — 가중 유클리드 거리 d = √(Σwᵢ(zᵢ−zᵢ*)²/Σwᵢ), 점수 100·exp(−d²/2). de-clustering 으로 같은 국면의 중복을 제거합니다.
  • 분산일 — r ≤ −X% ∧ V ≥ 전일×(1+Y%) ∧ CLV ≤ Z, lookback 안의 개수와 경과일.
  • 표본 독립성 — 유효 표본수 n_eff = n²/Σ max(0, 1−|Δt|/h) 와 독립 에피소드 수를 함께 보여 주고, 기본 신뢰구간은 에피소드 단위 cluster bootstrap 입니다.
  • 검증 — walk-forward(고정 분할 / expanding window), In-Sample 과 Out-of-Sample 을 구분해 과적합을 진단합니다.

자세한 설계·계산 방법론: docs/DESIGN_regime_lab.md. 결과는 리서치 도구이며 투자 권유가 아닙니다.

파라미터 · 지표 설명

② 시장 상태 정의 ③ 과거 유사 국면 ④ Forward Return ⑤ 통계적 검증

모든 feature 는 기준일 t 까지의 값만 사용합니다. 미래 값을 끌어다 쓰는 계산(backward fill, 미래 고점 등)은 어디에도 없습니다 — 그래야 "그때 그 자리에 서 있었다면 무엇을 보았을까"를 재현할 수 있습니다.

② 시장 상태 정의 — 오늘의 국면을 숫자로

여기서 만든 숫자들이 feature 벡터가 되고, ③ 에서 과거의 같은 벡터와 거리를 재게 됩니다. 각 feature 옆의 기본 가중치는 ③ 의 가중치 패널 초기값입니다. 0 이면 기본적으로는 거리 계산에 들어가지 않습니다 (직접 올려서 쓸 수 있습니다).

추세

SMA 창 (칩 선택)
단순이동평균을 계산할 기간들. SMA(w) = 최근 w 거래일 종가 평균. 앞의 w−1 일은 표본이 모자라 비워 둡니다(그래서 SMA200 을 쓰면 최소 200 거래일이 필요합니다). 고른 창마다 아래 feature 가 생깁니다.
  • 이격률 px_vs_sma{w} = (종가 / SMA(w) − 1) × 100 [%]. 종가가 이평선 위/아래 몇 %인가. 기본 가중치: SMA50·SMA200 = 1.0, 나머지 = 0
  • SMA 배열 점수 sma_stack: 인접한 SMA 쌍(짧은 것 > 긴 것)이 몇 쌍이나 정배열인지를 −1 ~ +1 로 환산. 예를 들어 20·50·200 을 골랐으면 쌍이 2개(20>50, 50>200) — 둘 다 맞으면 +1, 둘 다 틀리면 −1, 하나만 맞으면 0. 기본 가중치 1.0
기울기 구간 n (기본 20)
이평선이 오르고 있는지 내리고 있는지를 재는 뒤돌아보기 구간. sma{w}_slope = (SMA(w)_t / SMA(w)_(t−n) − 1) × 100 [%]. 같은 이격률이라도 이평선 자체가 상승 중인지 하락 중인지에 따라 국면이 다르기 때문에 따로 둡니다. 기본 가중치 0.5

모멘텀 / 위치

수익률 창 (칩 선택, 기본 5·20·60·120)
ret_k = (C_t / C_(t−k) − 1) × 100 [%]. 최근 k 거래일 동안 얼마나 올랐나. 짧은 창은 단기 과열/침체, 긴 창은 추세의 몸통을 봅니다. 기본 가중치: 20일 = 1.0, 60일 = 0.5, 나머지 = 0
고점 구간 (기본 252 ≈ 1년)
dd_52w = (C_t / max(C, 최근 252일) − 1) × 100 [%, 항상 ≤ 0]. 52주 고점 대비 낙폭입니다. 여기서 쓰는 고점은 t 까지의 최고 종가이고, 나중에 더 높은 고점이 나와도 소급하지 않습니다 — 미래를 훔쳐보지 않기 위해서입니다. 기본 가중치 1.5 — 전체 feature 중 가장 큽니다. 같은 상승장이라도 "신고가 부근"과 "고점에서 15% 빠진 자리"는 이후 전개가 전혀 다르기 때문입니다.

변동성

실현변동성 (기본 20일)
std(로그수익률, 최근 w일, ddof=1) × √252 × 100 [연율 %]. 종가-종가 기준이라 장중 흔들림은 보지 않습니다. 기본 가중치 1.0
ATR (기본 14일)
True Range = max(고−저, |고−전일종가|, |저−전일종가|) 를 Wilder 방식(α = 1/n 지수평활)으로 평균 낸 뒤 종가로 나눈 값 atr_pct = ATR / C × 100 [%]. 갭과 장중 레인지까지 반영한다는 점에서 실현변동성과 성격이 다릅니다. 기본 가중치 0 — 기본으로는 빠져 있습니다.

분산일 (Distribution Day)

"기관이 물량을 던진 날"을 세는 지표입니다. 아래 세 조건을 모두 만족하는 날만 분산일로 셉니다. X·Y·Z 를 직접 정할 수 있게 열어 둔 이유는, 이 정의가 원래 업계마다 조금씩 다르기 때문입니다.

X: 하락률 ≥ (기본 0.2%)
그날 종가 수익률이 −X% 이하. 기본값이면 −0.2% 보다 더 빠진 날.
Y: 거래량 증가 ≥ (기본 0%)
당일 거래량 ≥ 전일 거래량 × (1 + Y/100). 기본값 0 이면 "전일 이상". 20 으로 두면 "전일보다 20% 이상 증가한 날"만 셉니다. 거래량이 없거나 0 이면 그날은 아예 판정하지 않습니다 — ^IXIC 를 자동 내려받기로 쓰면 거래량이 부실한 경우가 있어, 데이터 품질 탭이 이를 알려 줍니다.
Z: CLV ≤ (기본 0.5)
CLV = (종가 − 저가) / (고가 − 저가) — 그날 레인지 안에서 종가의 위치입니다. 1 이면 고가 마감, 0 이면 저가 마감. 기본값 0.5 는 "레인지 하단 절반에서 마감". 많이 빠졌더라도 저점에서 되돌려 고가 부근에 마감했다면 매도 압력의 흔적으로 보지 않겠다는 뜻입니다. 고가 = 저가인 날은 중립(0.5)으로 처리합니다.
Lookback (기본 25 거래일)
dd_count = 최근 이 기간 안에 분산일이 몇 번 있었나. 기본 가중치 1.5 — dd_52w 와 함께 가장 큽니다.
dd_days_since = 마지막 분산일 이후 며칠 지났나(상한 있음). 기본 가중치 0

매크로 (미국 10년 금리) — 화면에 입력은 없지만 feature 로 들어갑니다

y10_level 수준
금리 자체의 레벨 [%]. 기본 가중치 0
y10_chg_{w}d 변화
y10(t) − y10(t−w) 를 bp(0.01%p) 단위로. 기본 가중치: 120일 변화 = 0.5, 나머지 = 0
금리는 레벨보다 변화 속도가 주식 국면을 가르는 경우가 많아 이렇게 두었습니다.
y10_pctile 백분위
최근 구간 안에서 금리가 상대적으로 어디쯤인지(0~100). 기본 가중치 0

③ 과거 유사 국면 — 닮은 날을 어떻게 고르나

두 가지 방식

Similarity (기본)
기준일의 feature 벡터와 거리가 가까운 순으로 뽑습니다. 아래 식을 씁니다.
Strict
"이격률 ≥ 3% 이고 분산일 ≥ 4개" 처럼 조건을 모두 만족(AND)하는 날만 고릅니다. 가중치가 설정돼 있으면 그 안에서 다시 유사도 순으로 정렬합니다. 조건이 빡빡하면 표본이 급격히 줄어드니 ④ 의 표본 경고를 같이 보세요.

거리와 점수 — 실제 계산식

① 정규화   z = (x − 중앙값) / (1.4826 × MAD)  robust
② 거리     d = √( Σ wᵢ (zᵢ − zᵢ*)² / Σ wᵢ )
③ 점수     score = 100 × exp(−d² / 2)

zᵢ* 는 기준일의 값, zᵢ 는 비교 대상 과거 날의 값, wᵢ 는 가중치입니다. 가중치 합으로 나누기 때문에 feature 를 더 켜도 거리가 자동으로 커지지 않습니다. 점수는 읽기 쉬우라고 붙인 환산값입니다 — d=0 → 100점, d=1 → 60.7점, d=2 → 13.5점. 90점대는 "상당히 닮았다", 30점 아래면 "닮은 날이 별로 없다"로 읽으시면 됩니다.

정규화 robust / zscore
단위가 제각각인 feature(%, bp, 개수)를 같은 자로 재기 위한 변환입니다. robust 는 중앙값과 MAD 를 써서 극단값에 덜 흔들립니다 — 2008년이나 2020년 3월 같은 날이 척도를 통째로 왜곡하는 것을 막습니다. zscore 는 평균과 표준편차를 씁니다.
중요: 이 척도는 기준일까지의 관측만으로 계산합니다(as-of). 전체 기간의 평균을 쓰면 미래 정보가 새어 들어갑니다.
가중치 패널
feature 별 wᵢ. 0 으로 두면 그 feature 는 거리에서 빠집니다. 무엇을 "같은 국면"으로 볼지를 정하는 가장 중요한 손잡이입니다.
최근 N일 제외 (기본 120 거래일)
기준일 바로 앞의 N 거래일을 후보에서 제외합니다. 어제·그제는 당연히 오늘과 닮았기 때문에, 빼지 않으면 상위 25개를 최근 몇 주가 독차지하고 "과거 사례"라고 부를 수 없게 됩니다.
De-clustering 간격 (기본 20 거래일)
뽑힌 match 끼리 최소 이 간격을 띄웁니다. 한 국면은 수십 일 이어지므로, 막지 않으면 2022년 9월 한 구간이 25개 중 20개를 채웁니다. 그러면 "25개 사례"가 실제로는 사건 2~3개일 뿐인데 통계는 25개인 척하게 됩니다. ④ 의 유효 표본 수(n_eff)와 같은 문제를 다루는 장치입니다.
episode 대표 유사도 최고 / 가장 먼저
한 덩어리에서 하루만 고를 때 가장 닮은 날을 쓸지, 가장 먼저 나온 날을 쓸지. "가장 먼저"는 국면의 진입 시점을 보고 싶을 때 유용합니다.
최장 horizon 이 채워진 날짜만
켜면 가장 긴 horizon(기본 120일)의 이후 수익률이 이미 존재하는 날만 후보가 됩니다. 끄면 최근 사례도 포함되지만 긴 horizon 의 표본 수가 짧은 horizon 보다 적어집니다. horizon 별 n 을 같게 맞추고 싶을 때 켜세요.
상위 N개 (기본 25)
De-clustering 을 통과한 날 중 점수 상위 몇 개를 쓸지. 늘리면 표본은 커지지만 덜 닮은 날이 섞입니다.

④ Forward Return — 그 다음에 무슨 일이 있었나

③ 에서 고른 날들 각각에 대해 그 이후 수익률을 모아 분포를 봅니다. fwd_h = (C_(t+h) / C_t − 1) × 100 [%]. h 는 거래일입니다.

horizon (기본 5 · 20 · 60 · 120 거래일)
며칠 뒤까지 볼지. 대략 1주 · 1개월 · 3개월 · 6개월에 해당합니다.
표시되는 통계
n 표본 수 · 평균 / 중앙값 · 승률(0%보다 큰 비율) · p25 / p75(사분위 — 분포의 폭) · 최소 / 최대 · 표준편차 · forward 최대낙폭(그 기간 중 겪은 최악의 하락, 평균·중앙값) · 신뢰구간.
평균보다 중앙값과 p25~p75 를 먼저 보세요 — 표본이 작으면 평균은 한두 사례에 끌려다닙니다. 최대낙폭은 "결과는 좋았지만 가는 길이 어땠나"를 말해 줍니다.
Baseline 비교
같은 통계를 전체 기간 아무 날에나 적용한 값입니다. 매칭 결과가 baseline 과 비슷하면, 그 국면은 특별한 정보가 없다는 뜻입니다. 이 비교 없이 "평균 +3%" 같은 숫자만 보면 안 됩니다.
Bootstrap 반복 (기본 2000)
신뢰구간을 만들기 위해 표본을 다시 뽑는 횟수. 늘리면 구간이 안정되고 계산은 느려집니다.
신뢰수준 (기본 0.95)
95% 면 "같은 방식으로 반복하면 이 구간이 참값을 95% 정도 담는다"는 폭입니다.
표본 경고 기준 (기본 10)
n 이 이보다 작으면 화면에 경고를 띄웁니다. 표본 5개짜리 "승률 80%" 는 숫자놀음입니다.
표본 독립성 전체 사용 / horizon 별 독립
이 프로그램에서 가장 중요한 손잡이 중 하나입니다. 20거래일 간격으로 뽑은 두 날의 120일 forward 는 100일이 겹칩니다 — 사실상 같은 사건을 두 번 세는 것입니다.
  • 전체 사용: 모든 match 를 쓰되, 겹침을 신뢰구간 계산에 반영합니다(기본).
  • horizon 별 독립: horizon 마다 최소 h 거래일 간격을 다시 강제해 완전히 겹치지 않는 표본만 씁니다. n 은 줄지만 가장 정직합니다.
CI 재표본 cluster / iid
cluster(기본)는 겹치는 날들을 한 덩어리(에피소드)로 묶어 재표본합니다. iid 는 날짜를 독립으로 취급합니다 — 비교용으로만 두었습니다. 실측해 보면 iid 는 신뢰구간을 h=60 에서 약 17%, h=120 에서 약 29% 좁게 만듭니다. 즉 실제보다 확신에 찬 그림을 그립니다.
유효 표본 수 n_eff
n_eff = n² / Σᵢⱼ max(0, 1 − |tᵢ−tⱼ| / h). 겹침을 벌점으로 매겨 "실질적으로 몇 개의 독립 사례인가"를 환산한 값입니다. n_eff ≈ n 이면 독립적인 사례들이고, n_eff ≪ n 이면 겉보기 n 이 부풀려진 것입니다. 예: n=25 인데 n_eff 가 11.5 로 나오면, 25개처럼 보이지만 실제 정보량은 11~12개입니다.

⑤ 통계적 검증 — 과거에 끼워 맞춘 규칙이 아닌지

이 화면이 막으려는 함정: 20년치로 가중치와 임계값을 고른 다음, 같은 20년에 대고 성적을 재고 "잘 맞는다"고 말하는 것. 여기서는 규칙을 고정한 채 앞으로 재생합니다.

평가일 t 마다 실제 사용자와 같은 자리에 섭니다 — 정규화 척도는 t 까지의 관측만, 후보는 자기 forward 창이 t 이전에 이미 닫힌 날만(t 시점에는 아직 진행 중인 사례의 결말을 알 수 없으므로 투표권이 없습니다). 그렇게 만든 신호(매칭된 날들의 forward 중앙값)를 t 에서 실제로 일어난 forward 와 비교합니다.

방식 고정 분할 / Expanding window
고정 분할: Train → Validation → Out-of-Sample 세 구간으로 한 번 자릅니다.
Expanding window: 기간을 조금씩 늘려 가며 반복 평가합니다. 한 번의 운 좋은 분할에 속지 않으려면 이쪽이 낫습니다.
Training 종료 / Validation 종료
구간을 가르는 날짜입니다. 이 날짜 이후 구간이 규칙을 만들 때 쓰이지 않은 진짜 시험지입니다.
평가 간격 (기본 5 거래일)
며칠에 한 번씩 평가할지. 1 로 두면 평가 횟수는 늘지만 인접한 평가끼리 겹쳐서 실제 정보량은 그만큼 늘지 않습니다.
검증 horizon (기본 20)
어느 horizon 의 예측을 채점할지.
결과 지표
방향 적중률(%) — 신호의 부호와 실제의 부호가 같았던 비율. 50%가 동전 던지기입니다.
Spearman 순위상관 — "신호가 큰 날이 실제로도 더 좋았나"를 순위로 봅니다. 이상치에 덜 흔들립니다.
Pearson — 값 자체의 상관.
읽는 법: In-Sample 은 좋은데 Out-of-Sample 에서 무너지면, 그 규칙은 노이즈에 맞춘 것입니다. 두 숫자를 나란히 놓고 보라고 IS/OOS 를 같이 표시합니다.

더 파고들려면 ④ 계산 감사 탭에서 특정 날짜의 모든 중간값(원본 → feature → 정규화 z → 가중 거리 → 점수 → 순위)을 단계별로 펼쳐 볼 수 있습니다.

① Python 설치 (처음 한 번)

python.org/downloads 에서 최신 버전을 받아 설치합니다. 설치 첫 화면에 "Add python.exe to PATH" 체크가 보이면 켜 주세요 — 안 보여도 괜찮습니다. Windows 에는 py 라는 실행기가 같이 깔리는데, 이건 PATH 설정과 상관없이 항상 동작합니다.

확인: 시작 메뉴 → powershell 실행 후

py --version

Python 3.13.x 같은 게 나오면 됩니다. 안 나오면 python --version 을 해 보시고, 그것도 안 되면 Microsoft Store 에서 Python 을 설치하세요(PATH 가 자동입니다). 이 안내에서 py 라고 적은 부분은, 그쪽이 되는 경우 python 으로 바꿔 쓰시면 됩니다.

② 프로그램 파일 내려받기 (Git 없이)

브라우저에서 아래 주소를 열면 ZIP 이 받아집니다.

https://github.com/uiheesin-ship-it/SUH_DH/archive/refs/heads/claude/funny-carson-ent3s7.zip

잘 안 되면 손으로: github.com/uiheesin-ship-it/SUH_DH → 왼쪽 위 브랜치 목록에서 claude/funny-carson-ent3s7 선택 → 초록색 Code ▾ → Download ZIP.

받은 zip 의 압축을 풉니다. 경로는 짧고 한글·공백 없는 곳이 좋습니다 (예: C:\SUH_DH). 풀린 폴더 안으로 들어가서 requirements.txt, app 폴더가 보이면 제대로 온 것입니다.

그 폴더에서 PowerShell 을 엽니다 — 파일 탐색기에서 그 폴더를 연 채로 위쪽 주소 표시줄을 클릭해 경로를 지우고 powershell 이라고 입력 후 Enter. 검은 창 맨 앞에 그 폴더 경로가 찍혀 있으면 맞습니다.

③ 필요한 패키지 설치 (처음 한 번, 2~5분)

py -m pip install -r requirements.txt

pandas·plotly 등을 받습니다. 노란 경고는 넘어가도 되고, 마지막에 Successfully installed ... 가 나오면 끝입니다.

④ 실행 (쓸 때마다)

py -m uvicorn app.main:app --port 8000

Mac / Linux 는 같은 폴더에서 ./run.sh 를 써도 됩니다.
Uvicorn running on http://127.0.0.1:8000 이 나오면 성공입니다. 이 검은 창은 닫지 마세요 — 켜져 있는 동안만 동작합니다. 끝낼 때는 그 창에서 Ctrl + C.

⑤ 사용

브라우저 주소창에:

127.0.0.1:8000/regime/

대시보드 전체는 127.0.0.1:8000 → 미장 → 기타 → Market Regime Lab.
Manual Upload 를 고르고 date, open, high, low, close, Volume 이 들어 있는 CSV 한 개를 올린 뒤 분석 실행. 이 브라우저에 데이터 기억을 켜 두면 다음에 열 때 파일과 지난 분석 결과가 그대로 복원됩니다(그 브라우저 안에만 저장됩니다).
인터넷이 되는 컴퓨터라면 Auto Download 로 ^IXIC 를 자동으로 받아 쓸 수도 있습니다 — 다만 자동 내려받기는 거래량이 부실한 경우가 있어 분산일 분석이 영향을 받을 수 있습니다.
